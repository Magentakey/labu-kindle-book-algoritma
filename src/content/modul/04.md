@@ pendahuluan | PENDAHULUAN | 1. Mengurutkan Seperti Menyusun Kartu

Bayangkan kamu bermain kartu. Kartu dibagikan satu per satu, dan setiap kali menerima kartu baru, kamu menyelipkannya ke posisi yang tepat di antara kartu-kartu yang sudah kamu pegang. Kartu di tanganmu selalu dalam keadaan terurut. Setelah kartu terakhir diselipkan, seluruh kartu terurut.

Itulah cara kerja **Insertion Sort** (pengurutan penyisipan). Algoritma ini sederhana, mudah ditelusuri dengan tangan, dan sangat cocok sebagai contoh pertama untuk mempraktikkan analisis running time dari Modul 03. Insertion Sort juga menarik karena running time-nya sangat bergantung pada isi data: untuk data yang sudah terurut ia bekerja dalam waktu linier, sedangkan untuk data yang terurut terbalik ia membutuhkan waktu kuadrat.

Modul ini membahas algoritmanya baris demi baris, menelusurinya dengan contoh dari bahan kuliah, lalu menurunkan rumus running time untuk kasus terbaik dan terburuk secara lengkap.

@@ algoritma | PEMBAHASAN INTI | 2. Algoritma Insertion Sort

### 2.1 Masalah pengurutan

**Masukan:** array $A[1..n]$ berisi $n$ bilangan sembarang. **Keluaran:** array yang sama, isinya disusun ulang sehingga $A[1] \le A[2] \le \cdots \le A[n]$ (terurut dari kecil ke besar). Insertion Sort mengurutkan *di tempat* (*in place*): elemen-elemen disusun ulang di dalam array itu sendiri tanpa array bantu.

Sebagai pengingat notasi array dari bahan kuliah: jika barisan 10, 20, 30, 40 disimpan di array $A$ berukuran $1 \times 4$, maka $A[1] = 10$, $A[2] = 20$, $A[3] = 30$, $A[4] = 40$. Bilangan 1, 2, 3, 4 disebut indeks, sedangkan 10, 20, 30, 40 adalah isi array.

### 2.3 Penjelasan setiap baris

| Baris | Penjelasan |
| --- | --- |
| 1 | Perulangan `for` untuk $j = 2$ sampai panjang array. Elemen $A[j]$ adalah "kartu baru" yang akan disisipkan. Ketika $j$ = panjang array + 1, perulangan berakhir dan algoritma selesai. Perulangan dimulai dari 2 karena $A[1]$ saja sudah dianggap terurut. |
| 2 | Simpan nilai $A[j]$ ke variabel `key`. Penyimpanan ini perlu karena posisi $A[j]$ nanti dapat tertimpa oleh pergeseran. |
| 3 | Mulai membandingkan dari elemen tepat di sebelah kiri `key`, yaitu indeks $i = j - 1$. |
| 4 | Ulangi selama $i > 0$ (belum melewati ujung kiri array) dan $A[i] > key$ (elemen di kiri masih lebih besar). Jika kondisi benar, jalankan baris 5 dan 6; jika salah, keluar dari `while` ke baris 7. |
| 5 | Geser $A[i]$ satu posisi ke kanan, ke $A[i + 1]$. |
| 6 | Mundur satu posisi: $i = i - 1$. |
| 7 | Letakkan `key` di posisi kosong yang ditemukan, yaitu $A[i + 1]$. |

*Tabel 1. Arti setiap langkah INSERTION_SORT.*

{{callout:benar|Mengapa algoritma ini benar?}}
Pada awal setiap putaran `for` dengan nilai $j$, subarray $A[1..j-1]$ berisi elemen-elemen asli posisi 1 sampai $j - 1$, sudah dalam keadaan terurut. Sifat yang selalu benar di awal setiap putaran ini disebut *invarian perulangan* (*loop invariant*). Sifat ini benar di awal ($j = 2$, subarray $A[1..1]$ hanya berisi satu elemen), tetap benar setelah setiap putaran (karena key disisipkan di posisi yang tepat), dan ketika perulangan berakhir dengan $j = n + 1$, sifat itu menyatakan bahwa $A[1..n]$ terurut. Cara pembuktian ini diuraikan lengkap oleh Cormen dkk. (2009, Bab 2.1).
{{/callout}}

Perhatikan pola pentingnya: $t_j$ selalu sama dengan banyaknya pergeseran ditambah satu. Satu pemeriksaan tambahan adalah pemeriksaan terakhir yang bernilai salah. Pola ini menjadi kunci analisis berikutnya.

@@ analisis | PEMBAHASAN INTI | 4. Analisis Running Time

Kita definisikan $t_j$ = banyaknya kali kondisi `while` pada baris 4 diperiksa untuk nilai $j$ tertentu. Nilai $t_j$ bergantung pada isi array, sehingga untuk sementara kita biarkan sebagai variabel.

### 4.1 Tabel cost dan jumlah operasi

| Baris | Pernyataan | Cost | Jumlah operasi |
| --- | --- | --- | --- |
| 1 | `for j = 2 to length[A]` | $c_1$ | $n$ |
| 2 | `key = A[j]` | $c_2$ | $n - 1$ |
| 3 | `i = j - 1` | $c_3$ | $n - 1$ |
| 4 | `while i > 0 and A[i] > key` | $c_4$ | $\sum_{j=2}^{n} t_j$ |
| 5 | `A[i+1] = A[i]` | $c_5$ | $\sum_{j=2}^{n} (t_j - 1)$ |
| 6 | `i = i - 1` | $c_6$ | $\sum_{j=2}^{n} (t_j - 1)$ |
| 7 | `A[i+1] = key` | $c_7$ | $n - 1$ |

*Tabel 5. Cost dan jumlah operasi setiap baris INSERTION_SORT.*

Alasan setiap jumlah operasi:

- Baris 1 dijalankan $n$ kali: untuk $j = 2, \dots, n$ (yaitu $n - 1$ kali) ditambah satu kali saat $j = n + 1$ yang mengakhiri perulangan.
- Baris 2, 3, 7 berada di dalam `for` tetapi di luar `while`, sehingga dijalankan sekali untuk setiap $j = 2, \dots, n$, yaitu $n - 1$ kali.
- Baris 4 dijalankan $t_j$ kali untuk setiap $j$, sehingga totalnya $t_2 + t_3 + \cdots + t_n = \sum_{j=2}^{n} t_j$.
- Baris 5 dan 6 adalah isi `while`, yang dijalankan satu kali lebih sedikit dari kondisinya (pemeriksaan terakhir bernilai salah), yaitu $t_j - 1$ kali untuk setiap $j$.

Running time adalah jumlah dari cost dikali jumlah operasi:

$$
T(n) = c_1 n + c_2 (n-1) + c_3 (n-1) + c_4 \sum_{j=2}^{n} t_j + c_5 \sum_{j=2}^{n} (t_j - 1) + c_6 \sum_{j=2}^{n} (t_j - 1) + c_7 (n-1).
$$

### 4.2 Kasus terbaik: array sudah terurut

Jika array sudah terurut dari kecil ke besar, untuk setiap $j$ kondisi $A[i] > key$ langsung bernilai salah pada pemeriksaan pertama. Tidak ada pergeseran, sehingga $t_j = 1$ untuk setiap $j$. Contoh dari bahan kuliah, $A = (2, 4, 12, 15, 30)$:

- Loop 1: $j = 2$, key $= 4$, $i = 1$. `while`: $A[1] = 2 > 4$? FALSE. $A[2] = 4$.
- Loop 2: $j = 3$, key $= 12$, $i = 2$. `while`: $A[2] = 4 > 12$? FALSE. $A[3] = 12$.
- Loop 3: $j = 4$, key $= 15$, $i = 3$. `while`: $A[3] = 12 > 15$? FALSE. $A[4] = 15$.
- Loop 4: $j = 5$, key $= 30$, $i = 4$. `while`: $A[4] = 15 > 30$? FALSE. $A[5] = 30$.
- Loop 5: $j = 6$, perulangan `for` berakhir dan algoritma selesai (setiap $t_j = 1$).

Dengan $t_j = 1$:

$$
\sum_{j=2}^{n} t_j = \sum_{j=2}^{n} 1 = n - 1, \qquad \sum_{j=2}^{n} (t_j - 1) = 0.
$$

Perhatikan bahwa penjumlahan dimulai dari $j = 2$, sehingga ada $n - 1$ suku bernilai 1. Substitusikan ke rumus $T(n)$:

$$
\begin{aligned}
T(n) &= c_1 n + c_2 (n-1) + c_3 (n-1) + c_4 (n-1) + c_5 \cdot 0 + c_6 \cdot 0 + c_7 (n-1) \\
&= (c_1 + c_2 + c_3 + c_4 + c_7)\, n - (c_2 + c_3 + c_4 + c_7).
\end{aligned}
$$

Dengan $a = c_1 + c_2 + c_3 + c_4 + c_7$ dan $b = -(c_2 + c_3 + c_4 + c_7)$, diperoleh **$T(n) = an + b$** (fungsi linier).

### 4.3 Kasus terburuk: array terurut terbalik

Jika array terurut dari besar ke kecil, setiap key lebih kecil dari semua elemen di kirinya. Semua $j - 1$ elemen di kiri harus digeser, lalu kondisi diperiksa sekali lagi ketika $i = 0$. Jadi $t_j = (j - 1) + 1 = j$. Contoh dari bahan kuliah, $A = (30, 15, 12, 4, 2)$:

| $j$ | key | Pergeseran | Array setelah putaran |
| --- | --- | --- | --- |
| 2 | 15 | 1 | 15, 30, 12, 4, 2 |
| 3 | 12 | 2 | 12, 15, 30, 4, 2 |
| 4 | 4 | 3 | 4, 12, 15, 30, 2 |
| 5 | 2 | 4 | 2, 4, 12, 15, 30 |

*Tabel 6. Kasus terburuk $A = (30, 15, 12, 4, 2)$: setiap key bergeser sampai ujung kiri.*

Dengan $t_j = j$, kita butuh deret aritmetika $1 + 2 + \cdots + n = \frac{n(n+1)}{2}$. Karena penjumlahan dimulai dari $j = 2$, suku $j = 1$ dikurangkan:

$$
\sum_{j=2}^{n} t_j = \sum_{j=2}^{n} j = \frac{n(n+1)}{2} - 1 = \frac{n^2 + n - 2}{2}, \qquad \sum_{j=2}^{n} (t_j - 1) = \sum_{j=2}^{n} (j - 1) = \frac{n(n-1)}{2} = \frac{n^2 - n}{2}.
$$

Substitusikan ke rumus $T(n)$:

$$
\begin{aligned}
T(n) &= c_1 n + c_2 (n-1) + c_3 (n-1) + c_4 \left(\frac{n^2 + n - 2}{2}\right) + c_5 \left(\frac{n^2 - n}{2}\right) + c_6 \left(\frac{n^2 - n}{2}\right) + c_7 (n-1) \\
&= \left(\frac{c_4 + c_5 + c_6}{2}\right) n^2 + \left(c_1 + c_2 + c_3 + \frac{c_4 - c_5 - c_6}{2} + c_7\right) n - (c_2 + c_3 + c_4 + c_7).
\end{aligned}
$$

Dengan $a = \frac{c_4 + c_5 + c_6}{2}$, $b = c_1 + c_2 + c_3 + \frac{c_4 - c_5 - c_6}{2} + c_7$, dan $c = -(c_2 + c_3 + c_4 + c_7)$, diperoleh **$T(n) = an^2 + bn + c$** (fungsi kuadrat).

### 4.4 Kasus rata-rata

Bahan kuliah hanya membahas kasus terbaik dan terburuk. Sebagai pelengkap: jika urutan awal data acak, rata-rata setiap key perlu dibandingkan dengan sekitar separuh elemen di kirinya, sehingga $t_j \approx j/2$. Penjumlahannya tetap menghasilkan suku $n^2$ (dengan koefisien kira-kira separuh kasus terburuk), sehingga kasus rata-rata Insertion Sort juga berorde kuadrat (Cormen dkk., 2009, Bab 2.2).

### 4.5 Verifikasi dengan program

Program berikut menjalankan Insertion Sort sambil menghitung $\sum t_j$ (eksekusi baris 4) dan $\sum (t_j - 1)$ (eksekusi baris 5). Hasilnya dibandingkan dengan rumus kasus terbaik ($n - 1$ dan $0$) serta kasus terburuk ($\frac{n^2+n-2}{2}$ dan $\frac{n^2-n}{2}$).

```python
def insertion_sort(arr):
    A = [None] + list(arr)           # A[1..n] seperti pseudocode
    n = len(arr)
    sum_t, sum_geser = 0, 0
    for j in range(2, n + 1):
        key = A[j]
        i = j - 1
        t = 1                        # pemeriksaan while yang pertama
        while i > 0 and A[i] > key:
            A[i + 1] = A[i]
            i = i - 1
            sum_geser += 1
            t += 1                   # pemeriksaan while berikutnya
        A[i + 1] = key
        sum_t += t
    return A[1:], sum_t, sum_geser

for data in ([12, 10, 15, 7], [2, 4, 12, 15, 30], [30, 15, 12, 4, 2]):
    print(data, "->", insertion_sort(data))

n = 1000
_, t_best, g_best = insertion_sort(range(n))          # terurut
_, t_worst, g_worst = insertion_sort(range(n, 0, -1)) # terurut terbalik
print(t_best, g_best, n - 1)
print(t_worst, g_worst, (n*n + n - 2)//2, (n*n - n)//2)
```

```text
[12, 10, 15, 7] -> ([7, 10, 12, 15], 7, 4)
[2, 4, 12, 15, 30] -> ([2, 4, 12, 15, 30], 4, 0)
[30, 15, 12, 4, 2] -> ([2, 4, 12, 15, 30], 14, 10)
999 0 999
500499 499500 500499 499500
```

Untuk contoh 12, 10, 15, 7: $\sum t_j = 2 + 1 + 4 = 7$ dan pergeseran $= 1 + 0 + 3 = 4$, sesuai penelusuran manual. Untuk $n = 1000$, hitungan program sama persis dengan rumus.

@@ makna | ANALISIS DAN HUBUNGAN KONSEP | 5. Makna Hasil Analisis

Isi data menentukan bentuk running time. Insertion Sort adalah contoh algoritma yang kasus terbaik dan terburuknya memiliki orde berbeda: linier untuk data terurut, kuadrat untuk data terurut terbalik. Dengan $n = 1000$, banyaknya pergeseran berkisar dari 0 sampai 499.500. Dalam notasi Modul 06, kasus terbaiknya $\Theta(n)$ dan kasus terburuknya $\Theta(n^2)$.

**Banyaknya pergeseran = banyaknya inversi.** Setiap pergeseran memperbaiki tepat satu pasangan elemen yang urutannya terbalik (disebut inversi). Karena itu Insertion Sort sangat cepat untuk data yang "hampir terurut" (inversinya sedikit) dan lambat untuk data yang banyak inversinya.

**Kapan Insertion Sort dipakai?** Ia cocok untuk data berukuran kecil atau data yang hampir terurut, mengurutkan di tempat (memori tambahan konstan), dan bersifat stabil: elemen bernilai sama tidak bertukar urutan karena kondisi pergeseran memakai $>$ dan bukan $\ge$. Untuk data besar yang acak, orde kuadratnya menjadi masalah serius. Modul 05 menunjukkan seberapa cepat $n^2$ tumbuh dibanding $n \lg n$, dan Modul 08 memperkenalkan Merge Sort yang kasus terburuknya $\Theta(n \lg n)$.

@@ kesimpulan | KESIMPULAN | 6. Kesimpulan

- Insertion Sort menyisipkan $A[j]$ ke posisi yang tepat di subarray $A[1..j-1]$ yang sudah terurut, untuk $j = 2, \dots, n$.
- Variabel $t_j$ menyatakan banyaknya pemeriksaan kondisi `while` untuk setiap $j$, sama dengan banyaknya pergeseran ditambah satu.
- Running time umum: $T(n) = c_1 n + (c_2 + c_3 + c_7)(n-1) + c_4 \sum t_j + (c_5 + c_6) \sum (t_j - 1)$.
- Kasus terbaik (data terurut): $t_j = 1$, sehingga $T(n) = an + b$ (linier).
- Kasus terburuk (data terurut terbalik): $t_j = j$, sehingga $T(n) = an^2 + bn + c$ (kuadrat). Kasus rata-rata juga kuadrat.
